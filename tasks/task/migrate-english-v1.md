> удаляется (`git rm`): в дерево v1.0.0 и в итоговую историю он попасть не

Цель: полный перевод проекта на английский (документация, комментарии,
строковые литералы) со схлопыванием всей истории в один коммит v1.0.0.
Оркестратор — основная сессия; исполнители — субагенты
`zai-coding-plan/glm-5.3-flash`, окно ≤4 параллельно, работа в worktree
`~/worktrees/laravel-domains/eng-NN`, вливание линейное (rebase + ff-only).

GitHub protection (снимок 11.11.2026, восстановить после этапа 7):
master и production — classic branch protection: linear history ON,
allow_force_pushes OFF, allow_deletions OFF, enforce_admins ON.
Открытых PR нет. Dependabot-ветки на origin осиротеют после squash — удалить при уборке.

## Этапы

- **Этап 1 — процессный контур:** AGENTS.md, tasks/*.md (24 файла, ~8.9k строк),
  .opencode/**/*.md. Статусы → английские. ~8 батчей.
- **Этап 2 — документация:** README, docs/ (21), deploy/**/README (5). ~15k строк, ~12 батчей.
- **Этап 3 — комментарии Go** (только комментарии, 454 файла, ~47k строк):
  батчи по пакетам в порядке убывания размера; автопроверка «дифф = только
  комментарии» + `go build` + `make lint`; полный `make test` каждые ~5 батчей.
- **Этап 4 — конфиги/скрипты:** migrations/*.sql (только `--`), systemd (комментарии
  + Description), yaml (комментарии, в workflows — имена шагов синхронно с pick()),
  deploy/*.sh (комментарии), conf/unbound/example. После первого sql-батча —
  `make test-integration`.
- **Этап 5 — строковые литералы:** прод-код (логи/ошибки) с одновременным
  обновлением ассертов тестов пакета; затем тест-строки. `make test` на батч
  (+ test-race для RACE_PKGS). Цитаты вывода программ в docs/runbooks
  обновлять в связке.
- **Этап 6 — генеральная проверка:** `git grep -nP '[А-Яа-яЁё]'` по всему
  репо, кроме testdata/ и deploy/docker/testbed/ → пусто; полный прогон
  test + test-race + lint + test-integration.
- **Этап 7 — squash + релиз (вне мандата этого цикла, с владельцем):**
  archive/ru-v1 → soft reset в корень → один коммит → тег v1.0.0 →
  временно включить force-push в protection → push -f master →
  push -f master:production (спокойное окно) → вернуть protection →
  удалить этот план-файл из истории (он исчезает сам: не попадает в squash)
  → уборка веток.

## Правила батча

- Один батч = один worktree = одна ветка `eng-NN` = один коммит на английском
  без T-номера, например `docs: translate internal/monitor comments to English`.
- Субагент не трогает файлы вне своего списка, не запускает тесты, не пушит.
- Верификация и вливание — оркестратор в основном дереве.
- Терминология — строго по глоссарию; отклонения и дополнения — в отчёт.
