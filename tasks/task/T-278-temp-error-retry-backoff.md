# T-278: Прогрессивный backoff ретраев temp_error (24 ч → 72 ч при attempts≥2)

- **Приоритет:** P1
- **Статус:** [новая]

## Контекст и симптомы

- 12–13.11.2026 доля temp_error аномальна: 63–69 % проверок при норме
  23–40 % (09–11.11: 40/23/36 %). Исследование на проде 13.11 (субагент,
  журнал + метрики + пробы curl/dig): 92,7 % ошибок HTTP-стадии — timeout,
  из них доказуемая часть — свойства удалённых сторон (SYN-молчание, tarpit
  после рукопожатия при здоровой локальной сети); ⅓ temp_error производит
  DNS-стадия (сломанные зоны upstream, SERVFAIL).
- 67 % temp_error-доменов падали ≥2 раза подряд (temp_attempts: 1 — 297k,
  2 — 266k, 3 — 140k) — отказы стойкие, не транзиентные.
- retry_mature 462–464 тыс./сут: фиксированный retry_after (24 ч, максимум
  3 ретрая) гоняет мёртвый корпус по кругу до 4 раз — до ⅔ повторной
  нагрузки q:http и PG.
- Фон: серия memcg OOM-киллов PG и спокойных окон 11–13.11 (см. T-279) —
  снижение повторной нагрузки ослабляет и этот паттерн.

## Корневая причина

Fixed retry_after не различает транзиентные и стойкие отказы: мёртвые
домены ре-энкюятся с той же частотой, что живые, а per-IP парковка
(T-165) добавляет самоинфлицированные таймауты в тот же поток.

## Требования

1. Прогрессивный backoff retry_after: attempts=1 → 24 ч (текущее
   поведение), attempts≥2 → 72 ч; параметр — конфиг-ключом.
2. Успешные проверки сбрасывают счётчик попыток (поведение живых доменов
   не меняется).
3. Рассмотреть расширение per_ip_overrides для парковочных префиксов
   (механизм T-165 уже есть) — срезает per-IP ожидания по мёртвым IP.

## Критерии приёмки

- Маржинальная доля retry_mature/checks снижается ≥2× (по счётчикам
  crawler_counters за сутки после деплоя).
- Распределение temp_attempts сдвигается к 1; приток q:http (домен/с)
  при том же темпе проверок не растёт.
- `make test` + `make lint` зелёные (+ `make test-race`, если затронут
  scheduler); `make test-integration`, если тронуты очереди/БД.
- Сутки на проде без новых OOM-киллов PG (при прочих равных, совместно
  с T-279 — не единственный фактор).
