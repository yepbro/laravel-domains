# Plan: triage of the surviving go-mutesting mutants (the 2026-10-20 baseline)

Source: a full `make mutate` run (94 min, 2877 mutants, score 0.673,
941 survivors) — `var/mutation/go-mutesting-report.html`, machine-readable
`var/mutation/report.json`. The survivor digests by group (the diff + line +
mutator + checksum for the blacklist) — `var/mutation/escaped/<task>.txt`.

Terminology (docs/mutation-testing.md §3): in mutate.log `PASS` — the mutant
is killed (good), `FAIL` — it survived (a hole in the tests). Here we work
only with the survivors.

## The policy per task

1. Every surviving mutant from the digest is triaged individually:
   - **kill with a test** — the main path: boundary conditions (`<= 0` vs
     `< 0`, a length of exactly 63/253 octets, `>` vs `>=`), error contents
     (the element number `i+1`, the field name), math (the windows, the
     round-robin keys, the percentages), the option defaults (±1 at the
     `Default*` constants and the thresholds);
   - **suppress with an annotation** (docs §4, the preferred suppression
     method): logging (`log.Debug/Info/Warn`, `slog.*`, `*.log().*`) — via
     `mutator-disable-regexp` over the call lines; hardware passthroughs
     without execution in the container (ioctl NVMe) —
     `mutator-disable-func`; purely cosmetic texts carrying no contract;
   - **the checksum blacklist** (`test/mutation/blacklist.txt`) — only if
     the mutant can be closed by neither a test nor an annotation
     (docs §4.2).
2. The decision per mutant is recorded in the commit body (the summary:
   killed by tests N, suppressed by annotations M, blacklist K — with the
   list of lines and the suppression rationale).
3. Tests — hermetic units in the style of the package (table-driven),
   without extending the time budgets of the existing tests.
4. Checks in a worktree: `COMPOSE_PROJECT_NAME=crawler make test`,
   `make lint`, a control spot mutation run
   `COMPOSE_PROJECT_NAME=crawler make mutate PKGS='./internal/<pkg>/...'`
   — the digest survivors are either killed or excluded (gone from the log).
5. Do not hide the annotations: each one carries a short comment on why the
   mutant is a false positive.

The final goal: score ≥ 0.75 over the full coverage, an update of the
docs/mutation-testing.md table and raising the nightly CI threshold.
