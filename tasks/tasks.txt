# План: разбор выживших мутантов go-mutesting (baseline 2026-10-20)

Источник: полный прогон `make mutate` (94 мин, 2877 мутантов, score 0.673,
941 выживший) — `var/mutation/go-mutesting-report.html`, машиночитаемо
`var/mutation/report.json`. Дайджесты выживших по группам (дифф + строка +
мутатор + чексумма для блэклиста) — `var/mutation/escaped/<задача>.txt`.

Терминология (docs/mutation-testing.md §3): в mutate.log `PASS` — мутант
убит (хорошо), `FAIL` — выжил (дыра в тестах). Здесь работаем только с
выжившими.

## Политика каждой задачи

1. Каждый выживший мутант из дайджеста разбирается индивидуально:
   - **убить тестом** — основной путь: граничные условия (`<= 0` vs `< 0`,
     длина ровно 63/253 октета, `>` vs `>=`), содержание ошибок (номер
     элемента `i+1`, имя поля), математика (окна, ключи round-robin,
     проценты), дефолты опций (±1 у `Default*` констант и порогов);
   - **погасить аннотацией** (docs §4, приоритетный способ гашения):
     логирование (`log.Debug/Info/Warn`, `slog.*`, `*.log().*`) — через
     `mutator-disable-regexp` по строкам вызовов; аппаратные passthrough
     без исполнения в контейнере (ioctl NVMe) — `mutator-disable-func`;
     чисто косметические тексты, не несущие контракта;
   - **блэклист чексумм** (`test/mutation/blacklist.txt`) — только если
     мутанта нельзя закрыть ни тестом, ни аннотацией (docs §4.2).
2. Решение по каждому мутанту фиксируется в теле коммита (сводка:
   убито тестами N, погашено аннотациями M, блэклист K — с перечнем
   строк и обоснованием гашения).
3. Тесты — герметичные юниты в стиле пакета (table-driven), без
   расширения временных бюджетов существующих тестов.
4. Проверки в worktree: `COMPOSE_PROJECT_NAME=crawler make test`,
   `make lint`, контрольный точечный мутационный прогон
   `COMPOSE_PROJECT_NAME=crawler make mutate PKGS='./internal/<pkg>/...'`
   — выжившие из дайджеста либо убиты, либо исключены (в логе пропали).
5. Аннотации не прятать: у каждой — короткий комментарий, почему мутант
   ложный.

Итоговая цель: score ≥ 0.75 по полному охвату, обновление таблицы
docs/mutation-testing.md и подъём порога ночного CI.

## Задачи

- **T-M01** [сделана] — `internal/monitor/alerts.go` (117 выживших; score
  пакета 0.59 — худший после dashboard). Дайджест:
  `var/mutation/escaped/T-M01-monitor-alerts.txt`.
  NVMe-посредник (L274–L403, ~55 мутантов: ioctl, struct layout, unsafe)
  — аппаратный passthrough, в CI не исполняется: погасить
  `mutator-disable-func` с обоснованием. Остальное — тестами:
  `formatGiB/MiB/KiB` (таблица на границах 1<<30/1<<20/1<<10 и внутри
  диапазонов), гистерезис и пороги DNS-алерта (`>=` vs `>` на
  AlertDNSRecoverShare, AlertDNSMinSamples), окно bad-hashes
  (AlertBadHashesWindow±1, `*` vs `/` на Interval), statfs
  (`Avail/Total * bs`), выбор худшего износа (`wears[1:]`, `>` vs `>=`),
  `humanBytes`-цепочка, дефолты опций (`Interval <= 0` vs `<= 1` и т.п.),
  `w.i = (w.i+1) % len(deltas)`.
- **T-M02** [сделана] — `internal/monitor/{badhashes,nearstats,historystats,
  zonestats}.go` (72 выживших). Дайджест:
  `var/mutation/escaped/T-M02-monitor-stats.txt`.
  Границы окон и лимитов (`badHashesBodyLimit = 4<<20`, таймауты зондов),
  ветки ошибок чтения/парсинга, инкременты счётчиков окон, сравнения
  `>=`/`>` на порогах срабатываний, SQL-обвязка — по политике.
- **T-M03** [сделана] — `internal/queue/message.go` (63 выживших). Дайджест:
  `var/mutation/escaped/T-M03-queue-message.txt`.
  Валидация сообщений — границы: `ZoneID/DomainID <= 0` против `< 0`
  (случай ID==0 обязан отклоняться), длина метки ровно 63 и CNAME/имя
  ровно 253 (`>` против `>=`, mutants `maxLabelLen 63/64`,
  `maxNameLen 253/252`), тексты ошибок с номером элемента (`i+1` против
  `i-1/i+0/i+2` — таблица с ошибкой во втором элементе пачки),
  `m.TaskID = NewTaskID()` при пустом (генерация на десериализации),
  `len(d.Payload) == 0`.
- **T-M04** [сделана] — `internal/queue/{redisq,backpressure,recover,
  reliab}.go` (96 выживших). Дайджест:
  `var/mutation/escaped/T-M04-queue-streams.txt`.
  redisq: `parseID` ms/seq (разрядность 64, base 10, не-число, порядок
  `>` против `>=` при равных ms), `DefaultRedisBlock`, `BUSYGROUP`,
  `start = "0"`, пустые msgs. backpressure/recover/reliab: пороги
  включения/выключения (`>` vs `>=`, ±1), окно оценки, счётчики.
- **T-M05** [сделана] — `internal/scheduler/{dispatch,enqueue}.go`
  (92 выживших). Дайджест:
  `var/mutation/escaped/T-M05-scheduler-dispatch.txt`.
  dispatch: взвешенный round-robin — `key = (rn-0.5)/w` (порядок выбора
  зон при фиксированных rn, деление против умножения), нормализация
  весов `w < 1 → 1`, `quota < 1 → 1`, `q.Limit < 1`, границы цикла
  `dispatchMaxRounds`, тай-брейк `zone.id` при равных key,
  `continue`→`break`. enqueue: границы `len(Name) > 253`, дефолты
  (`DefaultEnqueueBatch/IdleWait/Interval`, `<= 0` vs `< 0`), тексты
  ошибок с `i+1`.
- **T-M06** [сделана] — `internal/scheduler/{retry,backlog,recheck,lease}.go`
  (66 выживших). Дайджест:
  `var/mutation/escaped/T-M06-scheduler-cycles.txt`.
  Пороги повторов и экспоненты бэкоффа (±1 на константах и степенях),
  границы выборок backlog, перепланирование recheck, продление lease
  (`>` vs `>=` на таймингах — с фейковыми часами, без реальных пауз).
- **T-M07** [сделана] — `internal/render/{browser,proc,pool}.go`
  (67 выживших). Дайджест:
  `var/mutation/escaped/T-M07-render-browser.txt`.
  browser: `rootPID <= 0` (0 и -1), порог памяти `rss > 0 && rss >=
  MemoryThreshold` (rss==0, rss==threshold), ветки nil/ctx.Err().
  Взаимодействие с реальным Chromium — только через моки/интерфейсы,
  как принято в тестах пакета; запуск браузера в мутационном прогоне
  недетерминирован — ложные гасить по политике. proc: ожидание сигналов
  процесса, retry-паузы (фейковые часы). pool: границы пула.
