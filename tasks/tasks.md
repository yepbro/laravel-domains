## Как работать с файлом

- Задачи пронумерованы `T-001…T-135` и упорядочены по выполнению (сверху вниз).
- Статус задачи — метка в квадратных скобках, меняется редактированием:
  - `[новая]` — задача не начата;
  - `[в работе]` — задача выполняется;
  - `[сделана]` — задача завершена; по завершении волны строка задачи
    переносится в архив [`tasks_done.md`](./tasks_done.md) — здесь остаются
    только незавершённые задачи.
- Пример: `- **T-001** [в работе] — …`
- Внутри этапа задачи по возможности выполняются параллельно; между этапами — последовательно.
- Отступление от порядка этапов ТЗ §12: **хранилище контента** (этап 4 ниже) реализуется до HTTP-этапа, т.к. `http-worker` сохраняет контент через `ContentStore` (ТЗ §5.5, §5.7).

## Этап 10. Тестирование и приёмка (ТЗ §11)

- **T-092** [новая] — Нагрузочные замеры на целевом сервере: DNS QPS, HTTP RPS, скорость рендера, расход памяти по сервисам, скорость записи в БД и хранилище; уточнение значений по умолчанию в конфиге и оценка длительности первого цикла. ТЗ: §11.3, §13.2, §3.3.
  Заблокирована (2026-10-18): нужен развёрнутый целевой сервер (§10.1, systemd-деплой T-085…T-089); замеры на dev-машине не заменяют приёмку — числа обязаны быть с боевого железа. Разблокировка: после T-135 (физический деплой боевого сервера).
- **T-093** [новая] — Суточный прогон на целевом сервере в рамках бюджета памяти без срабатывания OOM-killer. ТЗ: §11.4 (п. 7), §3.2.
  Заблокирована (2026-10-18): требует целевой сервер под нагрузкой 24 ч (та же причина, что T-092); бюджет памяти закреплён юнитами T-085, проверка — фактическим прогоном. Разблокировка: вместе с T-092, после T-135.

## Этап 17. Развёртывание боевого сервера — физический деплой (2026-10-22)

Исполнение готового комплекта этапа 9 на целевом железе, разработки ПО
не содержит. Предусловие вне плана: целевой сервер по ТЗ §3.1/§3.2
(одна машина: 8 ГБ RAM, одна NVMe, один IP) получен и доступен по SSH;
факты железа (объём диска → раскладка томов) снимаются по месту —
`disks.md` §3. Пошаговый порядок — `operations.md` §3, детали —
`deploy.md` §4.

- **T-135** [в работе] — Физический деплой боевого сервера по ТЗ §10.1 (нативный systemd-деплой, Docker — только dev): установка и запуск комплекта T-085…T-089 на целевом сервере. Шаги (нумерация `operations.md` §3): (1) диски — тома LVM `lv_pg`→/var/lib/postgresql и `lv_content`→/var/lib/crawler/content (ext4, `noatime`) **до** `apt install postgresql` — `disks.md` §4, T-089; (2) пакеты ОС `postgresql-16`/`redis-server`/`unbound`/`smartmontools` + drop-in'ы бюджета памяти (`deploy/systemd/{postgresql@.service.d,redis-server.service.d,unbound.service.d}`), роль/БД приложения, боевые конфиги PG `deploy/postgres/postgresql.conf` (T-086) и Redis `deploy/redis/redis.conf` (T-087), конфиг unbound — `deploy.md` §4.1; (3) sysctl `deploy/sysctl/99-crawler.conf` в `/etc/sysctl.d` (T-088); (4) статические бинарники всех 9 сервисов + crawlerctl (CGO_ENABLED=0 -trimpath -s -w; бандл css лендинга T-124 для web) в `/opt/crawler/bin`, Chromium headless-shell в `/opt/crawler/chromium` — `deploy.md` §4.2–4.3; (5) системные пользователи `crawler-<сервис>` в группе `crawler` + рабочие каталоги (setgid 02775) — `deploy.md` §4.4; (6) `/etc/crawler/config.yaml` (обязательные правки примера: DSN, пути, `render.remote_url`, `monitor.listen`, `http.user_agent`, креды дашборда) + `/etc/crawler/crawler.env` — `deploy.md` §4.5; (7) юниты `deploy/systemd/*.service` + `crawler.target`, `systemctl enable --now crawler.target`; миграции применяются сервисами при старте автоматически (`schema_migrations`) — `deploy.md` §4.6–4.7; (8) мониторинг SMART/TBW `deploy/smartd/` — `deploy.md` §4.8; (9) публичный вход: nginx + TLS (лендинг — `deploy/nginx/crawler.example.conf` T-124, дашборд — отдельный server-блок T-131) — `deploy.md` §6; (10) проверка: `systemctl list-units 'crawler-*'` (все active), `curl /healthz` на портах метрик всех сервисов (9100…9108), `/opt/crawler/bin/crawlerctl status`; подать первую пачку доменов в `/var/lib/crawler/incoming/` и убедиться, что она проходит этапы конвейера до analyzer. Критерий готовности: конвейер работает на боевом железе, все проверки зелёные. Результат задачи разблокирует T-092 (нагрузочные замеры §11.3) и T-093 (суточный прогон §11.4 п. 7). Отчёт — журнал фактических значений железа и отклонений от сценария (если возникнут) в тело коммита/архивную запись при переносе в `tasks_done.md`.
