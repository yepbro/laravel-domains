## Как работать с файлом

- Задачи пронумерованы `T-001…T-137` и упорядочены по выполнению (сверху вниз).
- Статус задачи — метка в квадратных скобках, меняется редактированием:
  - `[новая]` — задача не начата;
  - `[в работе]` — задача выполняется;
  - `[сделана]` — задача завершена; по завершении волны строка задачи
    переносится в архив [`tasks_done.md`](./tasks_done.md) — здесь остаются
    только незавершённые задачи.
- Пример: `- **T-001** [в работе] — …`
- Внутри этапа задачи по возможности выполняются параллельно; между этапами — последовательно.
- Отступление от порядка этапов ТЗ §12: **хранилище контента** (этап 4 ниже) реализуется до HTTP-этапа, т.к. `http-worker` сохраняет контент через `ContentStore` (ТЗ §5.5, §5.7).

## Этап 20. Доработки по итогам нагрузочных замеров (2026-10-22)

Источник: T-092 (docs/load-measurements.md, «Находки для задач»).

- **T-138** [в работе] — Пустое тело ответа теряет ссылку на контент: `httpfetch.ToUTF8` на пустом теле возвращает `UTF8=nil` (charset.go), а http-worker ставит валидный хэш пустого тела и `Body=nil` → предохранитель ContentSaver гасит `content_hash` (Warn «тело записи недоступно», ~4% задач — парковки и 400/404/500 с `Content-Length: 0`). Нарушен контракт «хэш пустого тела валиден» (дедуп/классы эквивалентности пустых страниц, renderq-проход). Фикс + юнит-тесты (пустое 200/400, кэш-путь, saver). ТЗ: §5.5 п. 6, §5.7.
- **T-139** [в работе] — Пропускная способность http-этапа: task-параллелизм захардкожен (`httpworker.Options.withDefaults`: Concurrency=64/Consume=16/PerDomain=8) и конфигом не переопределяется (`http.concurrency` — только транспорт); цикл Run ждёт завершения всего окна из 16 доставок (batched barrier) при хвосте длительностей 20–25 с (total_timeout) → потолок ≈1.9 дом/с на боевом железе (замер T-092), первый цикл 350 млн ≈4.6 года против ориентира ТЗ «1–2 недели». Сделать параллелизм настраиваемым (поля конфига http.* с дефолтами по замерам), заменить барьер окна скользящим потреблением (следующее чтение при освобождении слотов), учесть per_ip_limit/head-of-line парковок; цель ≥100 дом/с в бюджете памяти (тела в полёте ≤ max_body_bytes). После фикса — повторный замер комплектом T-092. ТЗ: §3.3, §13.2.
- **T-140** [сделана] — Пакеты ОС для headless-shell: при T-135 из docker-образа взят только бинарь, fontconfig/шрифты не установлены → Skia `SkFontMgr_FontConfig: Not implemented` FATAL на части страниц, краш-луп до start-limit (10 рестартов), q:render копит попытки (замер T-092, §4 отчёта). Исправлено операционно на сервере 2026-10-22 (`apt install fontconfig fonts-liberation fonts-dejavu-core`, reset-failed+start); закрепить в deploy.md §4.3 (пакетный список рядом с libnspr4/libnss3) и чек-листе развёртывания, чтобы следующий деплой не воспроизвёл инцидент.
