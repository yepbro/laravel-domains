# Декомпозиция ТЗ «Сервис массовой проверки доменов и поиска сайтов на Laravel»

Источник: [`TZ_domain_crawler.md`](./TZ_domain_crawler.md) (версия 1.1).

## Как работать с файлом

- Задачи пронумерованы `T-001…T-095` и упорядочены по выполнению (сверху вниз).
- Статус задачи — метка в квадратных скобках, меняется редактированием:
  - `[новая]` — задача не начата;
  - `[в работе]` — задача выполняется;
  - `[сделана]` — задача завершена.
- Пример: `- **T-001** [в работе] — …`
- Внутри этапа задачи по возможности выполняются параллельно; между этапами — последовательно.
- Отступление от порядка этапов ТЗ §12: **хранилище контента** (этап 4 ниже) реализуется до HTTP-этапа, т.к. `http-worker` сохраняет контент через `ContentStore` (ТЗ §5.5, §5.7).

## Этап 1. Ingest — приём файлов (ТЗ §5.1)

- **T-013** [сделана] — Пакет `internal/watch`: наблюдение `incoming/` — fsnotify (create/write; рекурсивно: watch новых каталогов `<зона>/add|delete` добавляется на лету) + периодический полный обход как страховка (новая опция `ingest.scan_interval` 10ms..1h, по умолчанию 30 с, env `CRAWLER_INGEST_SCAN_INTERVAL`, стиль T-006); готовность — стабильность размера и mtime `stable_seconds` (10 с из §5.10), событие записи начинает окно заново даже при неизменной сигнатуре (грубый mtime ФС); выдаются только регулярные `*.txt` — `*.tmp`/`*.part`, скрытые файлы/каталоги и архив `processed/`/`failed/` верхнего уровня игнорируются (переименование в `*.txt` = событие создания готового имени); канал готовых файлов с буфером — backpressure блокировкой без потерь, повторная выдача исключена in-memory по пути+размеру+mtime (новый файл по тому же пути выдаётся снова; постоянная идемпотентность — ingest_files, T-021); отсутствующий каталог создаётся, исчезнувший восстанавливается обходом; логика стабильности — отдельный трекер с заглушаемым временем; тесты: трекер на фейковых часах + быстрый наблюдатель на реальном fsnotify (рост файла, tmp/part/скрытые, страховочный опрос, новые каталоги, backpressure, отмена, удаление до стабильности); `cmd/ingest` подключён через `OnRun` — логирует готовые файлы (точка интеграции T-014+). ТЗ: §5.1, §5.10.
- **T-014** [в работе] — Разбор пути `<зона>/add|delete/*.txt`: имя каталога зоны в unicode или punycode нормализуется в одну зону (без дублей); новая зона создаётся автоматически при первом файле (`is_active = true`). ТЗ: §5.1, §5.2 (пп. 6–7), §11.4 (п. 1).
- **T-015** [в работе] — Потоковый построчный парсер файлов: UTF-8, пропуски пустых строк и комментариев `#`, обработка CRLF и BOM; память не зависит от размера файла. ТЗ: §5.1, §3.5, §11.1.
- **T-016** [сделана] — Валидация строк: строка должна быть полным именем домена из зоны, указанной в пути; отклонение невалидных имён и слишком длинных; запись в лог `rejected` с причиной; порог доли ошибок на файл из конфига. Пакет `internal/ingest` (`validate.go`): валидатор файла — `NewValidator` нормализует зону пути (unicode/punycode — одна зона), `Line(номер, строка)` возвращает домен `{зона, метка, is_idn}` для загрузки T-017 либо причину отклонения, `Finish` — счётчики всего/принято/отклонено (по причинам) и вердикт «файл ошибочен»; строка нормализуется `idn.Normalize` (§5.2), зона результата сверяется с зоной пути (п. 6): совпадение с публичным суффиксом (составные `co.uk`, частные) или зона глубже суффикса (тестовые зоны вроде `crawl.test`, T-014); чужая зона и домен вложенной публичной зоны (`example.co.uk` при зоне `uk`) — `wrong_zone`, классы `idn.Error` — `empty/invalid/label_len/name_len/no_label`; составные метки (`магазин.рф.co.uk`) принимаются — контракт idn (корпус T-010); лог `rejected` — отдельный slog-логгер `NewRejectedLogger` (текстовый, стиль T-012, атрибут `service=rejected`; в записи файл, номер строки, строка обрезанная до 255 рун, причина; формат закреплён тестами); новая опция `ingest.max_error_ratio` (доля (0, 1], по умолчанию 0.1 — единичный мусор файлу не вредит, а не та зона/битый дамп дают долю ~1; env `CRAWLER_INGEST_MAX_ERROR_RATIO`, стиль T-006): доля отказов строго выше порога — файл ошибочен целиком (сигнал `failed/` для T-021), равная порогу и меньше — нет. ТЗ: §5.1, §5.2.
- **T-017** [в работе] — Загрузка в БД пачками (по умолчанию 50 000 строк) через `COPY` в staging-таблицу. ТЗ: §5.1, §3.5.
- **T-018** [новая] — Применение **add**: `INSERT … ON CONFLICT DO NOTHING`; существующий домен не меняется, кроме статуса `deleted` — возвращается в `new`/`pending`. ТЗ: §5.1.
- **T-019** [новая] — Применение **delete**: перевод статуса домена в `deleted` (домен остаётся в БД). ТЗ: §5.1, §13.1.
- **T-020** [новая] — Фоновая задача очистки удалённых доменов: удаление связанных результатов и ссылок на контент (уменьшение refcount). ТЗ: §5.1, §13.1, §8.
- **T-021** [новая] — Учёт и идемпотентность: запись отчёта в `ingest_files` (sha256, кол-во строк, добавлено/было/удалено/отклонено), защита от повторной обработки того же файла, перемещение файлов в `processed/`/`failed/` с лог-отчётом рядом. ТЗ: §5.1, §6.1.
- **T-022** [новая] — Юнит-тесты парсинга файлов: пустые строки, комментарии, CRLF, BOM, дубликаты, строки не из зоны. ТЗ: §11.1.
- **T-023** [новая] — Интеграционный тест ingest: файл в `incoming` → записи в `zones`/`domains`/`ingest_files`, повторы и delete-файлы. ТЗ: §11.2.

## Этап 2. Очереди и планировщик (ТЗ §4.2, §5.3)

- **T-024** [новая] — Интерфейс `Queue` (допустима замена бэкенда) и реализация на Redis Streams с consumer groups; форматы сообщений стримов `q:dns`, `q:http`, `q:render`, `q:analyze`, `q:dead` — только идентификаторы и минимальные данные (имя домена). ТЗ: §4.2.
- **T-025** [новая] — Надёжность очереди: `MAXLEN` на стримах; `XACK` только после записи результата в БД; возврат зависших сообщений через `XAUTOCLAIM`; счётчик попыток (по умолчанию 3) с переводом в `q:dead`. ТЗ: §4.2, §3.4.
- **T-026** [новая] — Backpressure: публикация новых задач только при длине очереди ниже порога (`queue_high_watermark`). ТЗ: §4.2, §5.3.
- **T-027** [новая] — Scheduler: выборка доменов `check_state = pending` пачками (1000–10 000), круговое распределение между зонами (опциональные веса зон), чтобы крупная зона не задерживала остальные. ТЗ: §5.3.
- **T-028** [новая] — Scheduler: перевод выбранных доменов в `queued` с отметкой времени (lease) и публикация пачек в `q:dns`. ТЗ: §5.3, §4.2.
- **T-029** [новая] — Scheduler: возврат доменов из `queued` в `pending` при истечении lease (по умолчанию 30 мин) без результата. ТЗ: §5.3.
- **T-030** [новая] — Scheduler: раз в сутки перевод `done` → `pending` для доменов с `last_checked_at` старше `recheck_interval` (по умолчанию 6 месяцев, минимум из конфига). ТЗ: §5.3, §3.3, §11.4 (п. 8).
- **T-031** [новая] — Scheduler: повторная проверка `temp_error` через `temp_error_retry_after` (24 ч), не более N раз подряд, далее итоговый статус по последней проверке. ТЗ: §5.3, §6.2.
- **T-032** [новая] — Тесты устойчивости: остановка воркера посреди пачки, потеря Redis (задачи восстанавливаются планировщиком, данные не теряются). ТЗ: §11.2, §3.4, §11.4 (п. 9).

## Этап 3. DNS-этап (ТЗ §5.4)

- **T-033** [новая] — Развёртывание и конфигурация локального Unbound: рекурсивный, prefetch, кэш ≈ 512–768 МБ; публичные резолверы как fallback (список в конфиге). ТЗ: §5.4, §3.2, deploy (Прил. А `/deploy`).
- **T-034** [новая] — Пакет `internal/dnsclient`: `miekg/dns`, собственный пул UDP-сокетов, TCP-fallback при усечении (TC), ретраи. ТЗ: §5.4.
- **T-035** [новая] — Настраиваемые лимиты DNS: параллелизм и QPS, адаптивное снижение при росте доли таймаутов, отключение AAAA конфигом при отсутствии IPv6. ТЗ: §5.4, §5.10.
- **T-036** [новая] — dns-worker: запрос A (и NS при необходимости) апекса; `NXDOMAIN` → статус `not_delegated`, субдомены не проверяются (RFC 8020); SERVFAIL/таймаут после ретраев → `temp_error`. ТЗ: §5.4 (пп. 1), §6.2, §7.
- **T-037** [новая] — dns-worker: запросы A/AAAA/CNAME по каждому включённому субдомену из `subdomains` с разворачиванием цепочки CNAME. ТЗ: §5.4 (п. 2).
- **T-038** [новая] — Wildcard-детект: запрос `<random>.<домен>`; субдомены, чьи адреса совпадают с wildcard-ответом, помечаются wildcard и не проверяются по HTTP (кроме апекса и `www`). ТЗ: §5.4 (п. 3), §8.
- **T-039** [новая] — Запись результата DNS: `domains.dns_mask`, `domains.status`; нет адресов → `delegated_no_address`; есть адреса → задача в `q:http` с адресами и CNAME. Идемпотентность записи. ТЗ: §5.4 (пп. 4–5), §6.1, §7, §3.4.
- **T-040** [новая] — Интеграционные тесты DNS на тестовом стенде: NXDOMAIN, SERVFAIL, wildcard, CNAME-цепочки, TCP-fallback. ТЗ: §11.2.

- **T-041** [новая] — Интерфейс `ContentStore` (`Put`, `Get`, `Delete`) в `internal/content` для последующей замены реализации (например, S3). ТЗ: §5.7.
- **T-042** [новая] — Формат пак-файлов: append-only, размер пака 512 МБ–1 ГБ, ротация; метаданные в `contents(hash, pack_id, offset, len, raw_len, refcount)`. ТЗ: §5.7, §6.1, §13.2.
- **T-043** [новая] — Сжатие zstd с обучаемым словарём; команда переобучения словаря в `crawlerctl`. ТЗ: §5.7, §13.2.
- **T-044** [новая] — Дедупликация по 128-битному хэшу (SHA-256 от нормализованного содержимого), счётчик ссылок; уменьшение refcount старого контента при перезаписи результата. ТЗ: §5.7, §8.

## Этап 5. HTTP-этап (ТЗ §5.5)

- **T-047** [новая] — Пакет `internal/httpfetch`: транспорт с таймаутами (connect 5 с, TLS handshake 5 с, заголовки 10 с, общий 20 с); подключение к заранее резолвенному IP; для редиректов на другие хосты — резолв через тот же резолвер с кэшем. ТЗ: §5.5 (пп. 1–2, таблица лимитов).
- **T-048** [новая] — Обработка редиректов: до `max_redirects` (8), детект циклов, учёт HTTP-редиректов и `<meta http-equiv="refresh">`; итоговая страница — в конце цепочки; хосты из `Location`/`meta refresh` в unicode приводятся к punycode. ТЗ: §5.5 (пп. 1, 4), §5.2 (п. 8).
- **T-049** [новая] — Лимиты и защита: макс. размер читаемого тела (2 МБ), защита от тарпитов (мин. скорость 2 КБ/с после первого байта), лимит соединений на один IP (3–4), короткий/отключённый keep-alive, глобальные лимиты соединений и RPS. ТЗ: §5.5 (таблица лимитов), §8.
- **T-050** [новая] — TLS: `InsecureSkipVerify = true`, но сохранение результата проверки сертификата, издателя, срока действия, SAN. ТЗ: §5.5 (п. 3), §8.
- **T-051** [новая] — Кодировки и сжатие: определение кодировки (заголовок, `meta charset`, детект) и приведение к UTF-8; `Accept-Encoding: gzip, br` с распаковкой и ограничением размера (защита от zip-бомб). ТЗ: §5.5.
- **T-052** [новая] — Честный `User-Agent` с контактами из конфига; запрашивается только главная страница `/`, `robots.txt` не запрашивается, минимум запросов на сайт. ТЗ: §5.5, §9.
- **T-053** [новая] — http-worker: задача на домен целиком, параллельная загрузка субдоменов внутри воркера, общий кэш «итоговый URL → результат» (не скачивать одну страницу дважды). ТЗ: §5.5 (пп. 1, 6), §4.2, §7.
- **T-054** [новая] — Логика вариантов http/https: один сайт → одна запись `variant = 0`; работает один протокол → одна запись с его `scheme`; разные сайты → две записи `variant = 0` (https) и `variant = 1` (http). Критерий одинаковости: итоговые хост+путь либо одинаковый хэш контента. ТЗ: §5.5 (п. 5), §7.
- **T-055** [новая] — Алиасы субдоменов: совпадение итогового URL или хэша контента с другим субдоменом домена → `alias_kind` (0/1/2) и `alias_subdomain_id`; контент хранится один раз. ТЗ: §5.5 (п. 6), §7.
- **T-056** [новая] — Сохранение контента через `ContentStore` с лимитом `max_store_bytes`; `content_hash` (16 байт) в `subdomain_results`; дедупликация парковок/заглушек. ТЗ: §5.5, §5.7, §8.
- **T-057** [новая] — Эвристика SPA-оболочки: мало видимого текста + корневые контейнеры `#root`/`#app`/`#__next`/`#__nuxt`, `<noscript>` с требованием JS, JS-редирект, `meta refresh` → публикация задачи в `q:render`; иначе сырой HTML — итоговый. ТЗ: §5.5 (п. 8), §13.2.
- **T-058** [новая] — Запись результата: все поля `subdomain_results` (адреса, CNAME, цепочка редиректов, статус, итоговый URL, TLS, заголовки, cookies, время ответа, код ошибки); статус домена `alive`/`no_http`; домен `done` после DNS/HTTP (рендер и анализ — асинхронно); после записи — публикация в `q:analyze`; идемпотентность; не записывать результат для домена в статусе `deleted`. ТЗ: §5.5 (пп. 7, 9), §6.1, §7, §8, §3.4.
- **T-059** [новая] — Юнит-тесты логики вариантов и алиасов: `bare → www`, `www → bare`, http → https, http ведёт на другой сайт. ТЗ: §11.1, §11.4 (п. 2).
- **T-060** [новая] — Интеграционные тесты HTTP на стенде: тарпит, бесконечный редирект, гигантское тело, zip-бомба, SPA-страница, некорректный сертификат. ТЗ: §11.2, §8.

- **T-073** [новая] — Набор YAML-правил Laravel по документации и реальным образцам заказчика (`testdata/laravel-samples`): версионные границы (vite/mix, inertia, livewire, cookies и т. д.). ТЗ: §5.8, §13.1, §13.3.

- **T-075** [новая] — Юнит-тесты движка правил: score, пересечение диапазонов, конфликты; прогон по корпусу образцов Laravel (с ожидаемыми `is_laravel` и диапазонами) и негативным образцам (не-Laravel). ТЗ: §11.1, §11.4 (пп. 4, 11), §13.3.
