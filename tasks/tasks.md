# Декомпозиция ТЗ «Сервис массовой проверки доменов и поиска сайтов на Laravel»

Источник: [`TZ_domain_crawler.md`](./TZ_domain_crawler.md) (версия 1.2).
Дополнительные ТЗ этапов: [`TZ_dashboard.md`](./TZ_dashboard.md) —
операторский веб-дашборд конвейера (этап 15).

## Как работать с файлом

- Задачи пронумерованы `T-001…T-206` и упорядочены по выполнению (сверху вниз).
- Статус задачи — метка в квадратных скобках, меняется редактированием:
  - `[новая]` — задача не начата;
  - `[в работе]` — задача выполняется;
  - `[сделана]` — задача завершена; по завершении волны строка задачи
    переносится в архив [`tasks_done.md`](./tasks_done.md) — здесь остаются
    только незавершённые задачи.
- Пример: `- **T-001** [в работе] — …`
- Внутри этапа задачи по возможности выполняются параллельно; между этапами — последовательно.
- Отступление от порядка этапов ТЗ §12: **хранилище контента** (этап 4, архив)
  реализовано до HTTP-этапа, т.к. `http-worker` сохраняет контент через
  `ContentStore` (ТЗ §5.5, §5.7).

## Этап 33. Хвосты по итогам дренажа рендер-долга (2026-11-01)

Follow-up-задачи из ревью и находок волн 30–32, не вошедшие в их
критерии приёмки.

- **T-215** [новая] — P3, `PartOf=crawler.target` для пары
  `crawler-chromium-recycle.{service,timer}` (кандидат из ревью T-208):
  сейчас после `systemctl stop crawler.target` очередной тик таймера
  запускает остановленный chromium (задокументировано оговоркой в
  docs/deploy.md §2.2 и operations.md). Фикс: директива в oneshot-сервис
  (PartOf гасит юнит вместе с набором) — сначала на сервере
  (источник истины), затем синхронно в `deploy/systemd/` + правка
  оговорок в docs. Критерий: на сервере и в репо директивы совпадают;
  `systemctl stop crawler.target` останавливает и таймерный рестарт не
  поднимает chromium до старта набора.

- **T-216** [новая] — P3, падающие live-тесты рендера на master:
  `WaitLive`/`ExtractLiveDataURL`/`TestBrowserLivePoolRender`
  (internal/render, контур CRAWLER_RENDER_TEST=1) ломаются на `data:`
  URL — `validateTaskURL` стал отвергать их позже написания тестов
  (предсуществующая поломка, найдена при T-213; CI не красит — контур
  opt-in). Починить (разрешить data: в тестовых задачах осознанно либо
  перевести тесты на http-фикстуры по образцу block_live_test.go).
  Критерий: `CRAWLER_RENDER_TEST=1 go test ./internal/render` — зелёный
  целиком; make test/lint не тронуты.

- **T-217** [новая] — P2, дедлок пост-проверок `crawlerctl zones
  collapse` (P2-находка окна T-198, 29.10): после успешной
  реконсиляции счётчиков процесс завис (futex_wait, ~10 потоков),
  сессии БД idle in ClientRead — CheckZonesLeftSQL выполнен сервером,
  результат не потреблён клиентом; transfer-соединение (Acquire)
  держало `DELETE FROM zones`; окно закрыто вручную (процесс снят,
  пост-проверки выполнены руками — все зелёные). Воспроизвести
  (вероятный вектор: непотреблённые rows однострочного агрегата при
  конкуренции соединений пула pool_size 5; интеграционный тест с
  малым пулом), найти и починить. Критерий: тест, детектирующий
  подвисание (таймаут вместо вечного ожидания), фикс, зелёный
  `make test-integration`.

- **T-208** [сделана] — P3, закрепить в репозитории таймер ресайкла
  Chromium: юниты `crawler-chromium-recycle.{service,timer}` (раз в 2 ч
  рестарт `crawler-chromium`) сейчас живут только на боевом сервере
  (`/etc/systemd/`, установлены 29.10 в окне T-198) — при переустановке
  хоста потеряются. Перенести в `deploy/systemd/`, дополнить
  `docs/deploy.md` §2.2 (remote-режим не позволяет воркеру рестартить
  чужой браузер — T-065; без ресайкла chromium копит память 400→950+
  МиБ за ~2 ч и таймауты рендера удваиваются, замер 29.10: ресайкл
  halved таймауты 227→110). Содержимое — с сервера (155.212.174.88,
  `/etc/systemd/system/crawler-chromium-recycle.*`); установка на прод
  уже выполнена — после мержа сверить файлы. Критерий: юниты в
  `deploy/systemd/`, docs обновлены, `make test`/`make lint` зелёные.

- **T-209** [сделана] — P3, юнит-шаблон второго Chromium с фикс
  `ReadWritePaths`: эксперимент 29.10 (второй chromium :9223 для
  `render-worker@9109`, откат — узкое место 4 vCPU) оставил рабочий
  юнит `crawler-chromium2.service` только на сервере. Закоммитить в
  `deploy/systemd/` как шаблон на случай возврата к двум браузерам на
  расширенном железе, зафиксировав найденный дефект юнита-копии:
  `ReadWritePaths` обязан указывать каталог профиля этого инстанса
  (`chromium2`), иначе `ProtectSystem=strict` блокирует запись и
  headless-shell падает в start-limit; упомянуть в `docs/deploy.md`
  §2.2 рядом с рецептом per-instance env. На проде юнит отключён —
  после мержа состояние сервера не меняется. Критерий: юнит в
  `deploy/systemd/`, дефект и фикс описаны в комментарии юнита и
  docs/deploy.md §2.2, `make lint` зелёный.
