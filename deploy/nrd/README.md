# Ежедневный входящий фид NRD smet.cz (cron)

Автоматическая подача списка новых доменов в конвейер: cron раз в сутки
скачивает `https://smet.cz/nrd/data/today.txt` (~8 МиБ, ~5·10⁵ доменов,
обновляется источником ежедневно) в наблюдаемую папку ingest — файл
появляется в `<ingest.dir>/add/`, дальше его обрабатывает сервис
`crawler-ingest` как обычную доставку ([`docs/incoming-files.md`](../../docs/incoming-files.md)).

Список — **зона-less**: домены разных зон в одном файле, зона каждой
строки выводится из самого домена по publicsuffix, недостающие зоны
создаются автоматически (docs/incoming-files.md §1) — разбивать по
каталогам зон не нужно.

| Файл | Куда ставится | Назначение |
|---|---|---|
| `fetch-nrd.sh` | `/usr/local/bin/crawler-fetch-nrd` (0755) | скрипт выгрузки: curl → `add/nrd-<UTC-дата>.txt.part` → атомарное переименование в `.txt` |
| `crawler-nrd.cron` | `/etc/cron.d/crawler-nrd` (0644) | запуск ежедневно в **19:17 UTC** |

## Установка

```bash
install -m 0755 fetch-nrd.sh /usr/local/bin/crawler-fetch-nrd
install -m 0644 crawler-nrd.cron /etc/cron.d/crawler-nrd
```

Зависимости — `curl` и `cron` (пакеты ОС, на боевом сервере есть).
Права root: файл кладётся владельцем `crawler-ingest:crawler` 0640,
как ручная доставка оператора.

Проверить прямо сейчас (не дожидаясь расписания):

```bash
/usr/local/bin/crawler-fetch-nrd
journalctl -t crawler-nrd-fetch --since -1d    # строка «OK: … sha256 …»
```

Дальнейшее — обычный жизненный цикл ingest: файл уходит в
`incoming/processed/add/`, домены — в БД, строка — в журнал
`ingest_files` (sha256 из лога совпадает с journal-полем), зоны видны
в `crawlerctl zones list`.

## Поведение и отказы

- **Расписание — 19:17 UTC.** Cron не умеет часовой пояс в строке:
  в `crawler-nrd.cron` часы переведены в местное время сервера
  (Europe/Moscow, UTC+3 → `17 22 * * *`); при смене зоны сервера
  (`timedatectl`) пересчитать обратно в 19:17 UTC.
- **Свежесть среза.** Источник обновляется ежедневно ~20:19 UTC, наш
  запуск в 19:17 UTC забирает срез предыдущих суток: между запусками
  ровно одно обновление источника — каждый день новый `sha256`, дублей
  по дедупу `ingest_files` не возникает.
- **Сбой сети/HTTP** — `curl --fail --retry 3`; файл не ставится
  вовсе (частично скачанный `.part` удаляется), запись `СБОЙ: …` в
  `journalctl -t crawler-nrd-fetch`, код выхода 1 — на эти же сутки
  других попыток нет, следующий запуск через сутки. Пропущенный день
  невосполним (источник хранит только `today.txt`) — при длительном
  сбое обновить вручную: `/usr/local/bin/crawler-fetch-nrd`.
- **Повторный запуск в тот же день** безвреден: тот же `sha256` —
  дедуп `ingest_files`, повторной обработки нет
  (docs/incoming-files.md §5).
- **Пустой файл источника** отвергается санитарной проверкой (не
  ставится, `СБОЙ` в лог); мусорные строки внутри файла фильтрует
  сам ingest (порог `ingest.max_error_ratio`, docs/incoming-files.md §4).

## Отмена

```bash
rm /etc/cron.d/crawler-nrd /usr/local/bin/crawler-fetch-nrd
```

Уже обработанные файлы/домены остаются в БД — при необходимости
вычистить список доставкой в `delete/` (docs/incoming-files.md §6).
